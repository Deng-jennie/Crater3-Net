# Crater3-Net

PyTorch implementation supplied for **Segmentation of Lunar Crater Sub-geomorphology based on an improved U-Net**.

This repository contains the supplied network implementation and newly added command-line adapters for training, inference and evaluation. It does not include the restricted Digital Moon database, original experiment checkpoints or historical train/validation/test assignments. Synthetic tests demonstrate software execution, not reproduction of the manuscript's numerical results.

## Models

| Name | Input | Decoder |
| --- | --- | --- |
| Crater3-Net | Three terrain channels | Max unpooling |
| Crater1-Net | DEM only in this adapter | Max unpooling |
| U3-Net | Three terrain channels | Transposed convolution |
| U1-Net | DEM only in this adapter | Transposed convolution |

The numerals **3/1 refer to input-channel count, not network depth**. All supplied variants have four pooling stages and widths 16, 32, 64, 128 and 256. Separate input convolutions are summed. Unpooling repeats recorded indices to match the expanded feature-channel count.

Five outputs represent background and four units: central peak, crater floor, crater wall and crater rim. The original numerical mapping of IDs 1..4 was not established from the supplied source. Provide the actual mapping as `class_names`; do not infer it from synthetic examples.

## Installation

Use Python 3.10 or newer and a separate virtual environment. Select a PyTorch build appropriate for your CPU/CUDA environment using https://pytorch.org/get-started/locally/.

```bash
python -m venv .venv
# Activate .venv using your operating system's command.
python -m pip install -r requirements.txt
```

Requirements express an adapter compatibility range, not the historical paper environment. See `docs/VALIDATION.md` for local tests. No GPU is required for small synthetic tests; real 512x512 training needs suitable hardware.

## Data interface

Prepare a numeric NumPy `.npz` file containing:

- `images`: finite array `(N,C,H,W)`; resolve NoData upstream.
- `masks`: integer IDs `(N,H,W)`, 0..4, for training/evaluation.
- `channel_order`: Unicode array matching the config; default DEM, slope, plan curvature.
- `class_names`: five distinct Unicode names in class-ID order; ID 0 is background.
- `sample_ids`: optional unique crater IDs, one per sample.

Register terrain layers to the same grid upstream. The adapter does not calculate terrain derivatives, repair NoData, reproject rasters or implement GIS vectorization/manual refinement. See `docs/DATA_FORMAT.md`.

**Legacy caution:** an inspected historical script reads DEM, plan curvature, slope and rescales to uint8 0..255. The supplied model instead declares DEM, slope, plan curvature and normalizes each sample/channel to 0..1. Verify the actual order and preprocessing before using historical weights. These files do not establish identical original experiment settings.

## Synthetic example

Artificial arrays are for execution checks, not lunar observations or a scientific benchmark.

```bash
python examples/make_synthetic.py --output data/synthetic
python -m unittest discover -s tests -v
python train.py --data data/synthetic/samples.npz --split data/synthetic/split.json --config configs/smoke.json --output outputs/smoke --device cpu
python inference.py --data data/synthetic/samples.npz --checkpoint outputs/smoke/best.pt --output outputs/predictions.npz --device cpu
python evaluate.py --data data/synthetic/samples.npz --split data/synthetic/split.json --checkpoint outputs/smoke/best.pt --output outputs/test_metrics.json --device cpu
```

## Real-data use

Supply authorized terrain arrays, verified label IDs and a JSON split with disjoint index lists `train`, `valid` and `test` covering all samples. Keep tiles from one crater/spatial group together. Fitting never consumes test samples; the lowest-validation-loss checkpoint is saved along with history and metadata.

Inference saves `(N,512,512)` class-ID masks **without geographic referencing**. Original-grid GeoTIFF/vector export requires a separate documented GIS step. Only checkpoints generated by this `train.py` are accepted; legacy weights are not automatically converted.

## Objective and metrics

The supplied objective uses sigmoid Dice with five one-hot channels, including background. Classes absent from the target batch contribute zero loss before the five-channel mean. Final predictions use argmax. This is not a softmax multiclass loss.

Foreground metric means exclude background but retain background-related false positives/negatives. mIoU includes a class present in reference **or** prediction; mPA includes a class only when present in reference. Undefined values become JSON `null`. Pooled-pixel and mean per-sample scores are reported separately. See `docs/IMPLEMENTATION.md`.
